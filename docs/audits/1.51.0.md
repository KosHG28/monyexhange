# Ревизия и пакет оптимизации 1.51.0

Область: запуск, ввод/курсы, редактор, чеки/настройки, сохранение, источники данных,
кэши и графические слои. Дизайн, BigDecimal и FitSize сохранены. Замедление знакомства
в три раза отменено владельцем; TripChoreography и длительности перехода не менялись.

## Подтверждённые находки и изменения

Корневой счётчик Navigation включён в реальную проверку 12 нажатий; нет второй изменяемой копии кошелька |
| QuoteCache | Ключом был весь Wallet по ссылке, а владелец — process-global singleton | Кэш принадлежит линии снимков состояния, учитывает финансовые поля, home/spend и версии источников. Выбор карты/страны не пересчитывает математику; имя/оформление/система обновляют ссылки CardQuote.card. Удалённые карточные списки выбрасываются |
| QuoteCache / publishMarket | Большой пересчёт нового источника мог оказаться на Main. ## Измерения и воспроизводимые проверки

- JVM-проверка 300 изменений только выбора: некэшированный расчёт — **271 232 байта**,
  прогретый кэш — **32 байта** в первом локальном прогоне. Это выделения в JVM-тесте текущего
  алгоритма с кэшем/без кэша, не проценты ускорения приложения и не измерение Realme.
- Unit-набор покрывает точность/инвалидацию кэша, актуальную карточную метаинформацию, наличные
  из банкомата, конкуренцию рынка и ввода, смену валюты, повтор после ошибки, последовательность
  сохранений, гонку HTTP и отмену. Существующие финансовые и анимационные контракты сохранены.
- `tools/ui-startup.py`: холодный запуск и сохранённый ввод в обеих темах.
- `tools/ui-recomposition.py`: 12 реальных нажатий; Header/CbrLine/Keypad/PayIcon/Navigation
  должны пропустить обновления, PriceField должен обновиться.
- `tools/ui-long-session.py`: 20 циклов редактор → просмотр сохранённого тестового чека → настройки,
  две темы. После 5/10/15/20 циклов: управляемый heap dump вызывает GC, HPROF удаляется и не
  загружается в artifacts. Слабые ссылки на закрытые receipt bitmap должны очиститься; Java/native
  heap сравниваются на последних двух прогретых точках с допуском 8 МиБ.
- Сохраняются meminfo и HWUI framestats (`Skia/OpenGL` эмулятора). Это диагностика рендера и
  графической памяти на эмуляторе, не физический GPU-профиль телефона и не обещание FPS на Realme.
- Снимки — только изменённые главный экран, редактор и просмотр тестового чека. Справочник
  не снимается, камера не открывается. Пробы слабыми ссылками/логами выключены в release;
  отсутствие диагностических тегов проверяется в DEX подписанного APK.

Фактические результаты UI/памяти хранятся в отчётах соответствующего запуска Android CI;
выпуск блокируется при провале сценария и до визуальной проверки текущего SHA.

## Обоснованные обходы, которые сохранены

- `MainActivity.runBlocking` используется только для отладочного demo/fixture, за проверкой
  debuggable/BuildConfig.DEBUG; обычная загрузка пользователя остаётся асинхронной.
- Задержка сохранения ввода 300 мс — debounce с flush при уходе, анимационные задержки —
  контракты интерфейса. Это не таймеры «подождать, пока всё заработает».
- Общий executor камеры не закрывается целиком: ML Kit может прислать позднее завершение.
  Рабочий поток освобождается по idle timeout; тестирует это AnalysisExecutorTest.
- ProGuard keep для регистратора ML Kit и порядок освобождения приватного входа OCR сохранены:
  их удаление без проверки нативного SDK способно вернуть прежний NPE/чтение освобождённой памяти.
- Нет новых @Stable/@Immutable для изменяемых моделей, принудительного GC в production,
  замены BigDecimal на Double или обхода lint. Предупреждения совместимости Android/SDK не
  подавлялись ради зелёной сборки.

## Границы вывода

Ревизия подтверждает исправления перечисленных путей, а не отсутствие всех возможных дефектов.
Аппаратная камера исключена по правилу владельца. Полное восстановление незавершённого черновика
карты после убийства процесса — отдельная функциональность; здесь проверяется сохранённый кошелёк
и выражение, а не автосохранение черновиков. Новые существенные поля состояния должны сопровождаться
проверкой подписок навигации, новые финансовые поля — проверкой инвалидации кэша.
